# Go client reference

## Configuration

Configure generation in `rad.config.yaml`:

```yaml
database_url: rad://127.0.0.1:7237
generate:
  - language: go
    output: generated
    package: db
```

Relative output paths resolve from the project configuration directory. Migrate and pull regenerate configured targets unless `--no-generate` is explicit.

For a one-off target, run:

```sh
rad --output json generate --file rad.schema.yaml --out generated --pkg db --lang go
```

## Accepted-state requirement

Generation reads the immutable snapshot selected by `rad.state/schema.lock.json`. It verifies that the desired schema is exactly that accepted schema. It never creates accepted state and refuses unapplied local edits.

Resolve failures by choosing the intended source of truth:

- Desired schema is correct: run `rad schema diff`, review, then migrate.
- Server schema is correct and local state needs recovery: run `rad schema pull`.
- Accepted state is correct and generation alone failed: fix the toolchain or output and rerun `rad generate`.

## Generated-code ownership

Generated files begin with `Code generated by rad generate. DO NOT EDIT.` Do not patch them by hand. Change `rad.schema.yaml`, accept the change, and regenerate.

The generated package embeds `SchemaVersion`, `SchemaHash`, and the canonical schema. Its client checks compatibility against the server before ordinary operations. A mismatch is an intentional guard against running typed code against another accepted schema.

Run `gofmt` through Rad's generator and commit generated output when the consuming repository's policy requires it. After generation, run the consuming Go package tests.
